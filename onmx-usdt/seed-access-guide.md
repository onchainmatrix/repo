# Seed Access Guide

## Seed Access Guide

Onchain Matrix Seed Access is designed to provide permissioned access to the Seed Round before the planned Public Sale / TGE stage.

The Seed Round is intended primarily to form the protocol-owned treasury base.

For a shorter purchase walkthrough, see:

**Seed Access → How to Buy ONMX**

### Current Seed Structure

| Term                              | Current Structure                                                    |
| --------------------------------- | -------------------------------------------------------------------- |
| Round                             | Seed                                                                 |
| Seed allocation                   | 2.5% of maximum ONMX supply                                          |
| Seed tokens                       | 25,000,000 ONMX                                                      |
| Seed price                        | $0.14 per ONMX                                                       |
| Public Sale / TGE reference price | $0.20 per ONMX                                                       |
| Reference discount                | 30% to the $0.20 reference price                                     |
| Vesting                           | 6-month cliff + 18-month linear vesting                              |
| Claims                            | Monthly after the cliff under the production vesting implementation  |
| Primary use of funds              | Treasury formation                                                   |
| Seed capacity                     | $3.5 million                                                         |
| Settlement asset                  | USDT, subject to the live interface and applicable transaction terms |
| Vesting / claims infrastructure   | Magna, powered by Kraken, once production onboarding is active       |

{% hint style="warning" %}
The Public Sale / TGE reference price is not a guarantee of future market price, liquidity, listing price, or appreciation.
{% endhint %}

## Before You Begin

{% stepper %}
{% step %}
### Use only the official Seed Access page

Begin from:

**onchainmatrix.com**

Do not follow Seed-payment instructions sent through unsolicited direct messages, unofficial social accounts, social-media replies, or third-party websites.

{% step %}
### Review the live Terms

Seed participation is permissioned.

Eligibility can depend on:

* jurisdiction,
* participant status,
* applicable legal restrictions,
* wallet and access controls,
* technical availability,
* acceptance of the current Terms.

The live Terms and access controls govern participation.

Access to the Seed interface does not itself guarantee eligibility.
{% endstep %}

{% step %}
### Use a wallet you control

Use a compatible wallet for which you control the relevant access credentials.

Never provide a private key, seed phrase, or recovery phrase to Onchain Matrix, Magna, a community moderator, a support representative, or any website.
{% endstep %}

## Participation Flow

{% stepper %}
{% step %}
### Access

Open the official Seed Access interface from onchainmatrix.com.

Confirm the domain and security of the connection.
{% endstep %}

{% step %}
### Confirm Eligibility

Complete the eligibility and participation confirmations presented by the live interface.

Do not attempt to bypass geographic, legal, wallet, or eligibility controls.
{% endstep %}

{% step %}
### Connect Wallet

Connect the wallet intended for the Seed transaction and future allocation verification.

Before approving a wallet request, confirm:

* domain,
* network,
* requested action,
* contract or spender address where displayed.
{% endstep %}

{% step %}
### Review Current Terms

Before submitting a transaction, verify:

* Seed price,
* ONMX allocation,
* settlement asset,
* settlement network,
* vesting terms,
* transaction amount,
* applicable restrictions,
* receiving or sale contract details.

{% hint style="warning" %}
If the live transaction terms differ materially from the current official documentation, do not proceed until the difference is resolved through an official channel.
{% endhint %}
{% endstep %}

{% step %}
### Prepare USDT

Use only the supported USDT token and network displayed in the live Seed interface.

Do not send USDT directly to an address unless that route is explicitly provided through the official interface and applicable Terms.
{% endstep %}

{% step %}
### Approve the Transaction

If token approval is required, review the spender address and approval amount before confirming.

Avoid unnecessary approvals beyond what the transaction requires where your wallet allows you to set the amount.
{% endstep %}

{% step %}
### Confirm Participation

Review the final transaction in your wallet before signing.

Confirm:

* network,
* contract address,
* settlement amount,
* token approval where applicable,
* estimated gas,
* transaction type.

Wait for blockchain confirmation after submission.
{% endstep %}

{% step %}
### Save Your Transaction Record

Keep:

* transaction hash,
* participating wallet address,
* date,
* settlement amount,
* ONMX allocation shown by the interface.
{% endstep %}
{% endstepper %}

## Magna Onboarding

Following a successful Seed allocation, the applicable participant record will be onboarded into **Magna, powered by Kraken**, under the production vesting process.

The email address or wallet associated with the allocation must be added to Magna before the participant can log in.

Once enabled, the participant can access:

**app.magna.so**

See:

**Seed Access → Magna Dashboard — Vesting & Claims**

## Vesting & Claims

Seed allocations are structured with:

**6-month cliff + 18-month linear vesting**

Monthly claim availability begins after the cliff under the production implementation.

### During the cliff

The Seed allocation remains restricted and is not immediately claimable.

### After the cliff

ONMX becomes eligible according to the applicable linear schedule.

The production Magna dashboard can display the participant's unlocked and claimable amount.

### At TGE

The Seed structure is not designed to provide unrestricted immediate Seed liquidity at TGE.

### Claiming ONMX

When ONMX is claimable, the Magna dashboard can display a Claim action for the participant's allocation.

## Common Issues

<details>

<summary>I cannot log in to Magna</summary>

First confirm that Onchain Matrix has added the email address or wallet associated with the allocation to Magna.

</details>

<details>

<summary>Wallet will not connect</summary>

Confirm that:

* the wallet is supported,
* the correct network is available,
* the browser or wallet extension is current,
* pop-up or connection requests are not blocked.

</details>

<details>

<summary>Seed Access is unavailable</summary>

Possible reasons include:

* the round has not opened,
* the round is paused or closed,
* eligibility requirements are not satisfied,
* jurisdictional restrictions apply,
* the interface is temporarily unavailable.

</details>

<details>

<summary>Wrong network</summary>

Do not submit a transaction until the wallet is connected to a network supported by the live Seed interface.

</details>

<details>

<summary>USDT balance is not visible</summary>

Confirm that the supported USDT contract is being viewed on the correct network.

</details>

<details>

<summary>Transaction remains pending</summary>

Check the transaction on the relevant block explorer before submitting another transaction.

</details>

<details>

<summary>Allocation is not claimable</summary>

A confirmed Seed purchase does not mean the full ONMX allocation is immediately transferable.

The cliff and vesting schedule still apply.

</details>

## Security Checklist

Before every Seed or Magna-related transaction:

* Start from official Onchain Matrix or Magna links.
* Confirm the current Terms.
* Confirm the connected network.
* Confirm the official contract or destination.
* Confirm the correct USDT token where applicable.
* Review transaction details in the wallet.
* Never share a seed phrase or private key.
* Ignore unsolicited payment or claim instructions.
* Save transaction hashes.
